# NNUE

Evaluation uses a SCReLU NNUE with a lazily updated accumulator stack and an AVX2 or AVX-512 output layer, trained on self-play data with its own CPU trainer.

## Current network

| Property | Value |
|---|---|
| File | `networks/net3.nnue`, embedded into the binary at build time |
| Architecture | `768 -> 1024x2 -> 1x8`, perspective network with 8 output buckets |
| Inputs | 768 = 2 sides x 6 piece types x 64 squares, squares flipped vertically for Black |
| Hidden layer | 1024 neurons per perspective, shared feature weights, accumulator updated incrementally on a lazy stack |
| Activation | SCReLU (`clamp(x, 0, QA)^2`) |
| Output buckets | 8 buckets by total piece count including kings: bucket = `min((pieces - 2) / 4, 7)`, so 2-5 pieces use bucket 0 and 30-32 pieces use bucket 7; each bucket has its own output weights and bias |
| Output | One neuron per bucket over the concatenated side-to-move and opponent accumulators (2048 inputs); only the bucket of the current position is evaluated |
| Parameters | 803 848 (`i16`, little-endian), 1 607 696 bytes |
| Quantization | QA = 255 (feature weights and biases), QB = 64 (output weights), output biases scaled by QA * QB |
| Evaluation scale | 400 (centipawns = output * 400 / (QA * QB)) |
| Inference | Output layer kernel picked at startup from the CPU: AVX-512 (`avx512f` + `avx512bw`, 32 lanes) or AVX2 (16 lanes) `madd` when the output weights of all buckets fit, portable fallback otherwise; per-lane sums stay in `i32` (checked at compile time for both widths of the 1024-wide layer) and the total is widened to `i64`. The kernel is chosen at run time, so every release build uses the widest one the CPU has; the build target (`x86-64-v2` / `v3` / `v4`) only changes what the compiler may use for the rest of the code, such as accumulator updates |
| Memory layout | Network rows and accumulators aligned to 64 bytes, so every 2 KB row starts on a cache line |

## Train commands

- `./target/release/arabica datagen <positions> [threads] [nodes] [output] [syzygy]` - plays self-play games (all cores, a soft limit of 2000 nodes per move by default: an iteration that reaches the limit is the last one, and a hard limit of 10x the soft one cuts runaway iterations; this averages about 5000 nodes per move) until `<positions>` positions pass the default filter and appends the games to `<output>` (default `data/arabica-<version>-n<nodes>.games`); rerunning with the same settings resumes the same file, and a file without the games header is refused; with `[syzygy]` (tablebase directories, as for `SyzygyPath`) a game that reaches the tables right after a capture or pawn move takes its result from WDL (cursed wins and blessed losses count as draws), is played on for 16 more plies with root moves restricted by DTZ so the result cannot change, and then ends; the search itself does not probe inside the tree, so recorded scores stay network evaluations; 5% of the random openings give material odds (one side loses its queen, a rook, a minor piece or one or two pawns) and skip the opening balance check, so the data covers large material imbalances with many pieces on the board; an adjudicated win is played on for 6 more plies before the game ends, so positions right after a decisive blunder are kept
- `./target/release/arabica-train train <data> <checkpoint> [epochs] [threads]` - trains the network on a games file or a position file (40 epochs, all cores by default), resumes an existing checkpoint and exports a `.nnue` network next to it after every epoch; the kept positions are held in memory at 32 bytes each
- `./target/release/arabica-train export <checkpoint> [network]` - quantizes a checkpoint into the engine's `.nnue` format (default: the checkpoint path with the `.nnue` extension)
